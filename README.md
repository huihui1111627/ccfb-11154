# 住户收支调查数据处理系统

从录入数据到加权结果的一条龙处理系统,带网页工作台。面向统计调查队季度住户收支抽样调查场景。

## 快速开始

```bash
python3 run_pipeline.py          # 端到端跑一遍并输出评估报告
cd survey_system && python3 app.py   # 启动网页工作台 http://127.0.0.1:8501
```

## 处理流程

```
虚构总体(10万户,真值留档)
  → 分层多阶段抽样(10层×PPS抽社区×等距抽户, 城镇超配, 共4500户)
  → 模拟录入(注入缺项/跳答错乱/越界/数量级错误/合计不符等约2800处)
  → 审核(范围检查 + 跳转逻辑 + 跨题逻辑)
  → 改正(自动修正确定性错误 + 审核员网页批注改正, 保留前后值)
  → 缺失插补(热卡法 + 回归法, 插补值带 *_imp 标记)
  → 事后加权(设计权数 × 人口控制总数 raking 校准)
  → 加权汇总(总量/均值/比例 + 抽样误差 + 95%置信区间 + 小样本自动加注)
  → 评估(各阶段估计 vs 总体真值; 插补前后偏差)
```

## 网页工作台板块

| 板块 | 路径 | 功能 |
|---|---|---|
| 总览 | `/` | 样本量、问题数、插补数等;一键重算 |
| 问卷结构 | `/structure` | 题型/跳转逻辑/取值范围(配置驱动, `config/questionnaire.json`) |
| 审核规则 | `/rules` | 系统规则与跨题规则清单及检出条数 |
| 疑问问卷 | `/queries` | 按规则/级别筛选, 逐份批注改正(保留改正前后值, `data/corrections.jsonl`) |
| 缺失插补 | `/imputation` | 各题插补量与方法; 插补值 vs 真值偏差 |
| 加权汇总 | `/summary` | 分组估计 + SE + 置信区间; 不可靠单元格自动加注 |

## 方法说明

- **跳转审核**: 按配置中的 `condition` 表达式判断每题"该答未答/不该答却答了"
- **跨题校验**: `when`/`check` 表达式(如 就业→年龄≤75、合计=分项之和、支出≤3倍收入)
- **热卡法**: 插补类 = 城乡×年龄段×性别, 类内随机 donor, 逐级回退
- **回归法**: B1工资、C1食品用 log线性模型(年龄、文化、城乡、性别)预测 + 残差重抽样噪声
- **事后加权**: 设计权数基础上, 按 性别×年龄段、城乡 人口控制总数做迭代比例拟合(raking)
- **抽样误差**: 最终类(ultimate cluster)法, 以 PSU 为最终抽样单位; 均值/比例用线性化
- **不可靠加注**: 单元格样本量 < 30 或 CV > 30% 自动标记

## 评估结论(本次模拟)

| 阶段 | 收入偏差 | 支出偏差 | 就业率偏差 |
|---|---|---|---|
| 脏数据(设计权数) | +2.16% | +4.29% | +0.67pp |
| 修正后未插补 | -1.23% | +2.21% | +0.67pp |
| 修正+插补 | -1.37% | +2.18% | +0.71pp |
| 修正+插补+事后加权 | -1.63% | +1.91% | +0.39pp |

插补精度(与干净样本真值对比): 回归法 B1 相对偏差 +2.3%, C1 -1.6%;
热卡法对零膨胀变量(如 B2 经营收入)波动较大, 属正常现象。

## 目录

```
survey_system/
  config/questionnaire.json   # 问卷结构配置(题型/跳转/范围/跨题规则)
  survey/
    schema.py       # 配置加载与表达式求值
    population.py   # 总体生成 / 分层多阶段抽样 / 错误注入
    validate.py     # 审核规则引擎
    correct.py      # 自动修正 + 人工批注改正(留痕)
    impute.py       # 热卡法 / 回归法插补
    weight.py       # 设计权数 + raking 事后加权
    estimate.py     # 加权估计 / 抽样误差 / 置信区间 / 可靠性标记
    pipeline.py     # 端到端流程与评估
  app.py            # Flask 网页工作台
  templates/        # 页面模板
  data/             # 生成的数据与结果
run_pipeline.py     # 一键跑通入口
```
