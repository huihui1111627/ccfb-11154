# raftkv —— 基于 Raft 的分布式分片键值存储

为城市燃气表远程抄表/阀控场景设计:阀控指令作为键值写入,Raft 保证单机房
故障不丢指令、不出现"双主"发相反指令;分片支撑全城键空间;状态页面实时
看集群。

## 构建与运行

```bash
cargo build --release

# 起 3 节点真实集群(TCP 互联)+ 状态页面 + 随机工作负载 + 一致性巡检
./target/release/raftkv demo --nodes 3 --web 8000 --base-port 9001 --dir /tmp/raftkv-demo
# 打开 http://127.0.0.1:8000

# 确定性模拟:2 万个随机故障场景(丢包/延迟/分区/重启/磁盘损坏),
# 每个场景结束用线性一致性检查器验证客户端历史
./target/release/raftkv sim --scenarios 20000 --seed 1 --ticks 3000 --threads 8

# 出问题按种子复现
./target/release/raftkv sim --scenarios 1 --seed <SEED>
cargo run --bin repro -- <SEED> [节点数]   # 转储该种子的完整终态

cargo test   # 单元 + 集成测试(逐条对应下面的需求)
```

## 设计

### 1. Raft 核心(`src/raft.rs`)

严格按论文 (Ongaro & Ousterhout):

- **选主/投票(§5.1-5.3)**:一个任期最多投一票(持久化 `voted_for`),
  随机化选举超时;**选举限制(§5.4.1)**:候选人日志至少和投票者一样新
  ((lastTerm, lastIndex) 字典序)才投票。网络分区时少数派凑不够多数,
  选不出主也提交不了任何条目——集成测试 `test_minority_partition_cannot_write`
  直接验证少数派不能写。
- **提交规则(§5.4.2)**:领导者只按复制计数提交**当前任期**的条目,
  旧任期条目随之间接提交;当选即追加空条目,让 ReadIndex/租约读尽快可用。
- **日志复制(§5.3)**:AppendEntries 一致性检查(prevLogIndex/prevLogTerm),
  冲突时回退到冲突任期的第一条(快速追赶),批量 64 条。
- **快照(§7)**:日志超过阈值在 applied 处打快照并截断;跟随者落后到
  nextIndex ≤ snapshotIndex 时直接发 InstallSnapshot。**不接受不新于本地
  commit 的快照**(否则状态机会回退且不再重放—— soak 抓出来过)。
- **成员变更(§6,联合共识)**:AddNode/RemoveNode 先进入联合态
  (C_old ∪ C_new,选举和提交都要新旧两个配置各自过半),联合条目提交后
  领导者自动追加 LeaveJoint 退出联合态。任何时刻最多一个变更在进行。
  加减节点期间集群一直可用(`test_joint_consensus_add_remove_node`)。
- **时间抽象**:Raft 不直接读时钟,宿主以 tick 注入(真实集群 1 tick = 10ms,
  模拟器 1 tick = 1 虚拟单位),这是确定性模拟的基础。

### 2. 线性一致读(§8):ReadIndex + 租约,两种都有

- **ReadIndex**:领导者记下当前 commit,向全组发带 ctx 的心跳,法定多数
  确认后,等状态机应用到该下标再本地读。不走日志、只走一轮心跳。
- **租约读(leader lease)**:法定多数心跳确认后,领导者在
  `election_timeout × 4/5` 内直接本地读(且要求 applied ≥ commit)。
  **时钟前提**:各节点时钟**速率**漂移有界,且漂移 ≪ 选举超时余量(我们留
  1/5,即 300ms 选举超时对应 60ms 余量)。本质是"跟随者的选举计时器不可能
  在领导者的租约到期前先走完"。用 NTP 校时、漂移在毫秒级时成立;**如果机器
  时钟可能跳变/暂停(虚拟机挂起、容器长时间被调度走),这个前提就不成立,
  请用 ReadIndex**——模拟器里两种读都过线性一致性检查,真实集群默认客户端
  也主要走 ReadIndex,租约只是优化。

### 3. 分片(`src/node.rs`)

- 键空间按范围分片,每片一个独立 Raft 组;组 0 是元数据组(全节点),
  保存分片目录。
- 片大小超过阈值,该片领导者在自己的 Raft 日志里提议 Split:
  **所有副本在同一下标确定性分裂**(旧组截左半,右半作为新组的引导快照,
  新组迟到者靠 InstallSnapshot 拿数据),然后由元组领导者把新目录注册进
  元数据组(幂等、可补注册)。
- 客户端目录过期时旧组回 WrongShard,客户端刷新目录重试,请求不报错。

### 4. 客户端(`src/client.rs`)

缓存分片目录和各组主节点提示;NotLeader 带提示重定向;主切换期间请求
**不报错**:退避后重新问主、等新主选出来再发(默认无限重试,可配超时)。
写命令内嵌回执令牌 (client, req_id),应用时由提案者按身份响应——
领导下台后同一下标被覆盖也不会给客户端"假成功"。

### 5. 存储与损坏检测(`src/storage.rs`)

- 每条日志记录、hardstate、配置、快照都带 CRC32;加载时逐条校验,
  连续性也校验(日志必须紧接快照、下标连续)。
- 发现损坏:节点以 **Refused** 角色恢复——不投票、不竞选、不响应复制,
  带病不参与(角色不可被任何消息洗回正常,需人工/运维修复后重新加入)。
- 模拟器可注入 bitrot(`MemFactory::corrupt`),测试同时用真实文件篡改
  验证 FileStorage 的 CRC 路径。

### 6. 状态页面(`src/web.rs`)

分五块:**节点状态**(角色/任期/commit/applied/日志长/快照点/存储 CRC)、
**日志复制**(领导者视角每个对等点的 matched/next)、**分片**(每片成员、
键范围、大小、状态机哈希、分裂历史)、**快照**(组/节点/下标/大小)、
**一致性检查**(副本同下标哈希比对、存储 CRC 复检、线性一致性检查器
跑客户端历史的结果),另有**选主历史**(每组的任期变化、当选者、
每次选主花了多少 ms)。

### 7. 确定性模拟与线性一致性检查(`src/sim.rs`、`src/checker.rs`)

- 单进程离散事件模拟:虚拟时间、可控丢包率/延迟区间、任意分区(按点对
  阻断)、节点崩溃重启(磁盘保留)、磁盘 bitrot 注入。所有随机性来自
  场景种子,**同一种子完全复现**(组内迭代顺序也全部排序固定)。
- 客户端并发随机读写,记录 (调用, 返回) 时间的历史;场景结束把历史交给
  自研线性一致性检查器:利用局部性按 key 分解为寄存器模型,对并发操作的
  所有合法排序做带回溯的搜索 + 记忆化。同时校验各副本状态机最终收敛。
- **不确定操作**:已发起但客户端没等到回执的操作(可能已提交也可能没有,
  例如领导者提交后崩溃、响应丢失——这是分布式系统固有的,无法避免)。
  场景结束时把仍在途的操作记为不确定操作,检查器对它们枚举"发生/没发生"
  两种可能,避免把系统的正确行为误判为违规。
- `run_soak` 多线程批量跑场景,失败打印种子,一行命令复现。

### 8. 请求去重(exactly-once 语义)

客户端给每个逻辑操作分配稳定 ID (client_id, op_seq),同一操作的所有重试
共用;状态机持久化每个客户端已应用的最大序号,重复命令直接跳过。没有
这层去重,重试会让同一操作生效两次——如果两次生效之间夹了一个删除,
键会被"复活"(soak 真的抓到过这个:Put 重试在 Del 之后落盘)。
回执令牌 (client, req_id) 则保证只有提案者按命令身份响应,领导下台后
同一下标被覆盖也不会给客户端"假成功"。

## 已知边界

- 未实现 pre-vote:被分区隔离的节点重新加入时可能用自己的高任期打扰一次
  现任领导者(引起一次不必要的重选,不影响正确性;§9.6 的"刚收到心跳
  不投票"规则已实现,这同时也是租约读安全的前提)。
- 分片只在同组节点间分裂,不做跨节点组的负载迁移(搬迁)。
